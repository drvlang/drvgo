# Reusing test selection across CI jobs

A six-package optional-test matrix took **1.362 s** with a shared selection
helper, down from **7.339 s** on `dcc285b` (**81.4% less wall time**). The
matrix modeled CI enumerating package directories on Linux. One package ran
a test, one had ordinary Go source without tests, and four were excluded by
a build tag, platform, cgo setting, or Go release constraint.

Each excluded directory used to run `go run` on the same helper with a fresh
Go build cache. Dynamic `allowEmptyTests` planners now share a Nix derivation
that compiles the helper with the selected SDK. Each planner still checks its
current sources and flags. Ordinary sources without tests still undergo real
compilation before drvgo emits an empty result.

| Dynamic CI workload | Before | After |
| --- | ---: | ---: |
| Six packages in one Nix build, cgo off | 7.339 s | 1.362 s |
| One excluded directory, Nix, cgo off | 3.408 s | 0.609 s |
| One excluded directory, nested iets, cgo on | 3.177 s | 0.442 s |
| One eligible test binary, Nix, cgo off | 1.145 s | 1.112 s |
| One library without tests, Nix, cgo off | 0.628 s | 0.629 s |
| Ordinary cgo command (`tests/fixture`), Nix | 0.889 s | 0.886 s |

These are median evaluation and realization times on Linux amd64 with Go
1.26.5 and Determinate Nix 3.24.1. Each run forced fresh planners with unique
forwarding names and warm package outputs. Before/after order alternated,
with one warmup pair excluded. The matrix used five measured pairs and each
single-package case used seven. Sandboxing was required, IFD and substitution
were disabled, and Nix used four jobs and two cores per builder. The two
revisions resolved to identical package outputs on every trial. After timing,
the harness executed the selected tests and verified each expected no-tests
marker.
[Individual samples, fixtures, flags and output paths](ci-round29-2026-11-19.json)

**First-use cost.** Every dynamic optional-test planner needs the selector as
an input, including jobs that find eligible tests immediately. A fresh helper
build with SDK inputs already local took **3.146 s** (median of five
reproducibility-checked rebuilds). The resulting store object was 3,035,448
NAR bytes, or 1,321,021 bytes in a zstd level 3 binary cache. A worker that
already has the SDK's timezone data needs only this additional object. Normal
command and strict test planners have no selector input.

The Linux amd64 planning-toolchain checks passed with Go 1.25.12, 1.26.5
and 1.26.6. Each selector handled a directory excluded by a future Go release
tag. Malformed build constraints, type errors, and invalid C code still failed
the build. Standalone optional-test exports passed with all three SDKs.

## Reproduction

The single-directory benchmark uses the existing CI harness. For example,
create a module containing one excluded source file and run the comparison
from the modified checkout.

```sh
src=$(mktemp -d)
printf 'module example.org/optional\ngo 1.25\n' > "$src/go.mod"
printf '//go:build optional\n\npackage optional\n' > "$src/optional.go"
nix run .#bench -- ci --before /path/to/dcc285b --after . \
  --source "$src" --test --allow-empty-tests --cgo 0 --runs 7 \
  --nix-option sandbox true --nix-option sandbox-fallback false \
  --nix-option substituters '' --nix-option always-allow-substitutes false
```

For the matrix, materialize `matrix.files` from the JSON in one source
directory and build the following expression with `nix-build --no-out-link`
and the recorded flags. Set `build` to the checkout's imported
`nix/dynamic.nix {}`, `src` to the fixture path, and `trial` to a unique name
for each invocation.

```nix
map (p: build {
  name = "ci-${trial}-${p}";
  inherit src;
  package = "./pkg/${p}";
  test = true;
  allowEmptyTests = true;
  cgoEnabled = false;
}) [ "portable" "library" "integration" "macos" "native" "future" ]
```
